# P7 — Voice quality: สิ่งที่ควรซื้อ vs สร้างเอง

เป้าหมาย: ยกระดับคุณภาพเสียงให้ใกล้ระดับแพลตฟอร์มเชิงพาณิชย์ (ตัดเสียงรบกวน, backchannel, ASR ไทย)
เอกสารนี้ระบุ **จุดต่อในโค้ดที่มีอยู่** และคำแนะนำว่าจะซื้อหรือสร้าง

## สถานะปัจจุบัน

| ความสามารถ | ตอนนี้ | ข้อจำกัด |
|---|---|---|
| ASR (ถอดเสียงผู้โทร) | `inputAudioTranscription` ของ Gemini Live | ไม่ได้เทรนกับสำเนียงถิ่น/ศัพท์เฉพาะ |
| ตัดเสียงรบกวน | ไม่มี DSP — แก้ด้วย VAD ที่ไวต่ำ (`StartSensitivity.LOW`) | เสียงรบกวนแรง ๆ ยังหลุดเข้าโมเดล |
| Backchannel ("อือ/ครับ") | ไม่มี — กัน barge-in หลอกด้วยความไว VAD | AI อาจหยุดพูดผิดจังหวะหรือไม่หยุด |
| TTS (เสียง AI) | Gemini Live prebuilt voices (`VOICE`) | จำกัดอารมณ์/สำเนียงไทย |
| Full-duplex / barge-in | มี (`realtimeInputConfig`, `interrupted`) | ต้องรักษาไว้ถ้าเปลี่ยน TTS |

## จุดต่อในโค้ด

```
โทรศัพท์ ──PCM8k──► audiosocket.ts ──pushPcm8k()──► agent.ts ──► Gemini Live
                                                        │
                    (A) noise suppression ──────────────┘  ก่อน upsample 8k→16k
                    (B) backchannel classifier ──────────── ตัดสินใจว่าจะส่งเข้าโมเดลไหม
                    (C) ASR ไทยภายนอก ──────────────────── ส่งข้อความแทน/เสริมเสียง
                    (D) TTS ไทยภายนอก ──────────────────── แทนเสียงที่โมเดลสร้าง
```

- **(A) Noise suppression** — แทรกใน `CallAgent.pushPcm8k()` ก่อน `this.up.process(pcm8)`
  ตัวเลือกที่ต่อง่าย: RNNoise (WASM/native), WebRTC Audio Processing Module, หรือ SpeexDSP
  ผลข้างเคียง: เพิ่ม latency ~5–20 ms — ยอมรับได้
- **(B) Backchannel** — หลัง VAD ตรวจว่ามีเสียงพูด: ถ้าสั้นกว่า ~400 ms และเป็นคำสั้น ๆ ให้ถือว่าเป็น
  "ฟังอยู่" แล้วไม่ต้องส่งเข้าโมเดล (หรือส่งเป็นสัญญาณให้โมเดลพูดต่อ)
  เริ่มจาก heuristic (ความยาว + พลังเสียง + คำในลิสต์) ก่อน ไม่ต้องใช้โมเดล
- **(C) ASR ไทยภายนอก** — ถ้าต้องการคุณภาพสูงสุด: ส่ง PCM8k ไปยัง ASR ของผู้ให้บริการ (streaming)
  แล้วส่งข้อความเข้าโมเดลผ่าน `sendClientContent` แทนการส่งเสียง
  **ข้อควรระวัง**: จะเสีย prosody/อารมณ์ที่โมเดลได้จากเสียงโดยตรง และ latency จะสูงขึ้น
  ทางเลือกที่สมดุล: ใช้ Gemini Live ต่อ แต่เก็บ ASR ภายนอกไว้เป็นชั้นตรวจสอบ/บันทึก
- **(D) TTS ไทยภายนอก** — แทนที่ `emit('audio', ...)` ด้วยเสียงจาก TTS
  **ข้อควรระวัง**: จะเสีย full-duplex barge-in ที่ Gemini Live ให้มา ต้องทำ barge-in เอง
  แนะนำ: รักษา Live audio ไว้ ถ้าต้องการเสียงไทยเฉพาะทางให้ทดลอง A/B ก่อน

## คำแนะนำ: ซื้อหรือสร้าง

| ส่วน | แนะนำ | เหตุผล |
|---|---|---|
| ASR ไทย (สำเนียง/ศัพท์เฉพาะ) | **ซื้อ/ใช้ vendor** | ต้องมีข้อมูลเทรนจำนวนมาก ต้นทุนสร้างสูงมาก |
| TTS ไทยหลายอารมณ์ | **ซื้อ/ใช้ vendor** | เทรนเสียงคุณภาพสูงต้องใช้ทีมเฉพาะทาง |
| Noise suppression | **ใช้ไลบรารีสำเร็จรูป** (RNNoise/WebRTC APM) | โอเพนซอร์สคุณภาพดี ต่อใน 1 จุด |
| Backchannel | **สร้างเอง (heuristic ก่อน)** | ต้นทุนต่ำ วัดผลได้เร็ว |
| VAD / barge-in | **ใช้ของ Live API ที่มี** | ทำงานได้แล้ว ปรับค่าความไวได้ |

## ลำดับที่ควรทำ

1. **วัดก่อน** — เก็บชุดเสียงจริง (สายโทรศัพท์จริง) แล้ววัด WER ของการถอดเสียง + อัตรา barge-in ผิดพลาด
2. **(A) noise suppression** — ต่อ RNNoise/APM แล้ววัด WER ซ้ำ (มักได้ผลชัดและต้นทุนต่ำ)
3. **(B) backchannel heuristic** — ลดการตัดบทผิดจังหวะ
4. **(C)/(D)** — พิจารณา vendor เมื่อ 1–3 แล้วยังไม่พอ

## หมายเหตุการวัดผล

- ทุกจุดใน `agent.ts` เขียน log อยู่แล้ว (`latency`, `transcript`, `tool`, `action`) และลง DB ผ่าน `store`
  จึงเทียบ before/after ได้จากข้อมูลจริง ไม่ต้องเดา
- เป้า latency ถึงเสียงแรก < 1 วินาที (ปัจจุบันวัดได้ ~0.4–1.4 วินาที)
